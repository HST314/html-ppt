# PAGE LOGIC PATTERNS

本文件是「页面语义分析层」的查表依据：**什么样的内容 → 使用什么样的页面结构**。

使用方式：
1. 对每页完成五步判断（主结论 / 信息层级 / 逻辑关系 / 视觉结构 / 视觉焦点）。
2. 在本文 13 类逻辑中选定**唯一主导逻辑**，查表得到视觉结构与组件库 role。
3. 按信息分组规则把 ≥4 条信息归为 2–4 个视觉信息组，把组落到结构区块上。
4. 把结论登记到 `state/page_semantics.md`，并将显式 `<!-- role: xxx -->` 写回 deck.md。

铁律：
- 禁止未经查表直接使用“标题 + 多条横向 bullet”版式。
- 一页一个主导逻辑；出现第二个主导逻辑时拆页。
- 结构必须承载语义：观众只看版面骨架（不看文字）也应能读出条目之间是并列、先后还是主次。

---

## 0. 通用决策流程

```
每页信息条目
  │
  ├─ ① 写主结论：一句话，写不出 → 拆页/并页
  │
  ├─ ② 数条目：<4 条 → 直接进入 ④ 选逻辑
  │            ≥4 条 → ③ 先分组
  │
  ├─ ③ 信息分组（强制 2–4 组，规则见第 15 节）
  │
  ├─ ④ 判逻辑：条目/信息组之间是什么关系？→ 查 13 类对照表（第 1–13 节）
  │      平等无先后 → 并列        两方对照   → 对比
  │      原因推结果 → 因果        步骤有先后 → 流程
  │      绑定日期   → 时间轴      程度渐强   → 递进
  │      一核多点   → 中心辐射    首尾相接   → 闭环
  │      两维交叉   → 矩阵        上下包含   → 层级
  │      数字为证   → 数据        物为主体   → 产品展示
  │      场景故事   → 图文叙事
  │
  └─ ⑤ 定视觉焦点：全页唯一锚点（最大字号 / 最大面积 / 最高对比，三者至少居一）
```

### 13 类逻辑 → 组件库 role 速查

| 逻辑类型 | 首选 role | 备选 role | 视觉焦点落点 |
| --- | --- | --- | --- |
| 并列 | two-column | bullets（受限，须附理由）、gallery、kpi | 组标题行 / 首卡片 |
| 对比 | compare | two-column | 对照分界点 |
| 因果 | two-column | compare | 结果区 |
| 流程 | timeline | two-column（编号步骤卡） | 第一节点或终点成果 |
| 时间轴 | timeline | — | “现在”节点 |
| 递进 | timeline | two-column（阶梯条） | 最高一级 |
| 中心辐射 | image-hero | two-column（中心+分支） | 中心核 |
| 闭环 | two-column | bullets（环列，受限） | 循环起点即终点 |
| 矩阵 | table | two-column（2×2 卡片） | 目标象限 |
| 层级 | table | two-column（分层条 L1…Ln） | 最高层 L1 |
| 数据 | kpi | table | 核心数字 |
| 产品展示 | image-hero | image-side、gallery | 产品主体 |
| 图文叙事 | image-side | image-hero | 场景主图 |

`cover` / `toc` / `section` / `closing` / `quote` 为叙事骨架页，不参与 13 类逻辑判定。

## 1. 并列

- **适用内容特征**：多个条目地位平等、无先后顺序、无因果推导；典型为“三类需求 / 四项原则 / 若干特性”。条目可互换位置而不改变含义。
- **识别信号**：“A、B、C 三类”“同时满足”“包括以下方面”。
- **结构示意**：
  ```
  ┌────────── action title（主结论）──────────┐
  │ ┌─组1─┐ ┌─组2─┐ ┌─组3─┐   ← 2–4 个等宽卡片 │
  │ │标题 │ │标题 │ │标题 │      组标题可见     │
  │ │2–4条│ │2–4条│ │2–4条│                    │
  │ └─────┘ └─────┘ └─────┘                    │
  │ So-what：takeaway 强调栏                    │
  └────────────────────────────────────────────┘
  ```
- **role 映射**：2 组用 `two-column`；3–4 组用卡片网格（two-column 双行或 kpi 式块）；纯图并列用 `gallery`。
- **视觉焦点**：第一个信息组的组标题，或主结论本身。
- **避免**：超过 4 组仍硬排一页；把有先后的内容伪装成并列。

## 2. 对比

- **适用内容特征**：两方（或前后两态）在同一维度上对照：方案 A vs 方案 B、before vs after、竞品 vs 本品、徽章（近观收藏）vs 海报（远观传播）。
- **识别信号**：“对比”“vs”“之前/之后”“优势”“两种尺度”。
- **结构示意**：
  ```
  ┌────────── action title ──────────┐
  │ ┌──── A 侧 ────┐ ‖ ┌──── B 侧 ────┐│
  │ │ 维度1 描述    │ ‖ │ 维度1 描述    ││
  │ │ 维度2 描述    │ ‖ │ 维度2 描述    ││  ← 同一基线逐行对照
  │ └─────────────┘ ‖ └─────────────┘│
  │ 结论条：对照后唯一判断（焦点）              │
  └──────────────────────────────────┘
  ```
- **role 映射**：`compare` 首选；维度多于 4 行时改 `table`（左列维度、右两列对象）。
- **视觉焦点**：对照后的结论条；或差异最大的一行。
- **避免**：三方以上塞进对比结构（改矩阵或并列）；只列两面事实却不给对照结论。

## 3. 因果

- **适用内容特征**：条目间存在推导链“因为 … 所以 …”：问题→根因→对策、投入→产出、策略→结果。
- **识别信号**：“由于”“因此”“导致”“源于”“带来了”。
- **结构示意**：
  ```
  ┌────────── action title ──────────┐
  │ ┌─因───────┐   ┌─果───────────┐ │
  │ │ 原因/条件  │ → │ 结果/影响（焦点）│ │
  │ │ 可多条分组 │   │ 落到主结论     │ │
  │ └─────────┘   └─────────────┘ │
  └────────────────────────────────┘
  ```
- **role 映射**：`two-column`（左因右果）；单因果+强数字结论可用 `kpi` 承载结果区。
- **视觉焦点**：结果区（观众记住的是“所以怎样”）。
- **避免**：因果链超过三级（拆成两页或改流程）；把相关关系写成因果。

## 4. 流程

- **适用内容特征**：完成一件事的有序步骤，步骤可编号：概念→深化→制作→安装→验收；设计→打样→量产→运输。
- **识别信号**：“第一步/第二步”“流程”“环节”“先…再…最后”。
- **结构示意**（参考视觉：编号胶囊链，节点 01→05 依次咬合）：
  ```
  ┌────────── action title ──────────┐
  │ [01 步骤]→[02 步骤]→[03 步骤]→[04 步骤] │
  │   说明       说明       说明       说明   │
  │ 编号显著、方向箭头显著；终点成果为焦点       │
  └──────────────────────────────────┘
  ```
- **role 映射**：`timeline`（3–6 节点）承载编号步骤；步骤含丰富图文时用 `two-column` 编号步骤卡。
- **视觉焦点**：终点节点的交付物，或当前所处节点。
- **避免**：节点超 6 个（合并为阶段或拆页）；把无顺序的并列硬编号。

## 5. 时间轴

- **适用内容特征**：信息强绑定日历时间：过去—现在—未来、roadmap、里程碑、行业演进 2003→2023。
- **识别信号**：具体年份/季度/日期，“历程”“规划”“演进”。
- **结构示意**（参考视觉：时间长河——一条主轴穿起各时期，节点挂事件，"现在"放大）：
  ```
  ┌────────── action title ──────────┐
  │ 过去──────[现在]──────未来          │
  │ 2003 事件   2026 事件(焦点)  2027 计划 │
  │ 节点必须含：日期＋事件＋结果           │
  └──────────────────────────────────┘
  ```
- **role 映射**：`timeline`。每个节点必须含日期 + 事件 + 结果（沿用 NARRATIVE.md 格式 `2026-03｜上线灰度｜投诉率下降 18%`）。
- **视觉焦点**：“现在”或下一个里程碑节点。
- **避免**：节点无日期（说明不是时间轴，改流程或递进）。

## 6. 递进

- **适用内容特征**：程度、深度或阶段逐级加强：认识→相信→理解→体验；材料→器件→电路→算法→系统验证（能力链）。
- **识别信号**：“从…到…再到…”“逐步加深”“层层递进”“升级”。
- **结构示意**（参考视觉：阶梯/层级链，每级高于前一级，末级最大）：
  ```
  ┌────────── action title ──────────┐
  │ 级1 → 级2 → 级3 → 级4 → [级5 焦点]   │
  │ 每级：名称＋一句"比上一级多了什么"      │
  │ 视觉高度/明度逐级抬升                 │
  └──────────────────────────────────┘
  ```
- **role 映射**：`timeline`（节点按递进排序）或 `two-column` 阶梯条；层级语义更强调“上下包含”时改用第 10 节「层级」。
- **视觉焦点**：最高一级（终点状态）。
- **与流程的区别**：流程回答“先做哪步”，递进回答“深到哪层”；步骤可并行展开时用流程，程度单向累积时用递进。

## 7. 中心辐射

- **适用内容特征**：一个核心概念派生多个应用/触点/领域：同一视觉 DNA 连接徽章、海报、体验；共同感知原点走向多领域智能。
- **识别信号**：“核心是…，辐射到…”“统一…多触点”“一个原点，多个场景”。
- **结构示意**（参考视觉：中心原点 + 四周气泡分支）：
  ```
  ┌────────── action title ──────────┐
  │      分支A        分支B            │
  │        \        /                │
  │        [中心核：焦点]              │
  │        /        \                │
  │      分支C        分支D            │
  │ 中心核最大；分支 2–4 个、体量一致     │
  └──────────────────────────────────┘
  ```
- **role 映射**：`image-hero`（中心核用大图/大数字容器，分支以标注环绕）；纯文字用 `two-column`（左中心核、右分支清单）。
- **视觉焦点**：中心核。
- **避免**：分支超过 5 个（先分组）；分支之间有先后（改流程）。

## 8. 闭环

- **适用内容特征**：链路首尾相接形成循环：参观体验三重价值闭环（决策认同→公众理解→讲述传递→再强化决策）、PDCA、运营增长飞轮。
- **识别信号**：“闭环”“循环”“飞轮”“相互强化”“回到起点”。
- **结构示意**：
  ```
  ┌────────── action title ──────────┐
  │        节点1 → 节点2              │
  │        ↑        ↓                │
  │   [中心：循环主张]  节点4 ← 节点3    │
  │ 首尾箭头必须闭合；节点 3–4 个        │
  └──────────────────────────────────┘
  ```
- **role 映射**：`two-column`（一侧环列节点、一侧中心主张）；节点含数字时用 `kpi` 围合。若环节是固定先后顺序且无回授语义，改用「流程」。
- **视觉焦点**：中心循环主张；或循环中价值最高的一环。
- **避免**：环节超过 4 个（合并为阶段）；把单向链条画成环（虚假闭环）。

## 9. 矩阵

- **适用内容特征**：信息由两个维度交叉定位：重要性×紧急性、受众×场景、成本×效果。
- **识别信号**：“两个维度”“象限”“组合”“矩阵”。
- **结构示意**：
  ```
  ┌────────── action title ──────────┐
  │        维度B高                    │
  │   象限2      │   [象限1 焦点]      │
  │ ─────────────┼───────────── 维度A │
  │   象限3      │    象限4           │
  │        维度B低                    │
  └──────────────────────────────────┘
  ```
- **role 映射**：2×2 卡片网格用 `two-column` 双行；维度取值多于 2 档用 `table`（行列双维度）。
- **视觉焦点**：主结论指向的目标象限（通常是右上）。
- **避免**：维度超过两个（改层级或并列）；象限内只放一个格子有内容（信息量不足，改并列）。

## 10. 层级

- **适用内容特征**：信息存在上下包含或高低秩序：L1 基底→L4 灯光的材料分层、战略→战术→执行、金字塔能力模型。
- **识别信号**：“最上层/底层”“分层”“等级”“L1/L2/L3”“由…支撑”。
- **结构示意**（参考视觉：分层条 L1–L4 显式编号，自上而下展开；或金字塔）：
  ```
  ┌────────── action title ──────────┐
  │ L1 ── 最高层（焦点）──────────────  │
  │ L2 ──── 展开层 ────────────────    │
  │ L3 ────── 支撑层 ──────────────    │
  │ L4 ──────── 基础层 ────────────    │
  │ 每层：编号＋名称＋一句作用            │
  └──────────────────────────────────┘
  ```
- **role 映射**：`table`（层级编号列 + 名称列 + 作用列）或 `two-column`（左层级示意图、右 L1–Ln 分层条）。
- **视觉焦点**：最高层 L1（或金字塔尖）。
- **避免**：层级超过 5 层（合并）；层与层只是并列关系（改并列）。

## 11. 数据

- **适用内容特征**：页面的证据主体是数字：KPI、目标对比、同比环比、基准测试、经营结果。
- **识别信号**：多个百分比/倍数/绝对值，“提升/下降/达成”“对比目标”。
- **结构示意**：
  ```
  ┌────────── action title ──────────┐
  │  [大数字 焦点]   数字2      数字3    │
  │  说明+上下文    说明       说明     │
  │  每个数字必须带：目标对比/同比/基准   │
  └──────────────────────────────────┘
  ```
- **role 映射**：`kpi`（3–5 项）；行列规整的明细用 `table`（末行高亮结论）。
- **视觉焦点**：最大的那个核心数字。
- **避免**：数字无上下文（必须带对比口径）；KPI 超过 5 个（先分组或改表格）。

## 12. 产品展示

- **适用内容特征**：页面的主角是具体物/界面/作品：纪念徽章、海报、仪表盘截图、工艺细节。
- **识别信号**：有高权重产品图/截图，文字在解释“它是什么、好在哪”。
- **结构示意**（参考视觉：英雄主体 + 证据条——大主体占据视觉中心，底部/侧部一排 3–4 个验证点）：
  ```
  ┌────────── action title ──────────┐
  │ ┌───────────────┐  卖点1          │
  │ │  产品主体大图    │  卖点2          │
  │ │  （焦点）       │  卖点3          │
  │ └───────────────┘                │
  │ [证据1] [证据2] [证据3] [证据4] 验证条 │
  └──────────────────────────────────┘
  ```
- **role 映射**：`image-hero`（横版主体大图）或 `image-side`（竖图/截图）；多角度细节用 `gallery`；截图必须触发 `screenshot-frame`。
- **视觉焦点**：产品主体图。
- **避免**：图片出血、叠字（沿用 PROJECT_IMAGES.md 硬约束）；卖点超过 4 条不分组。

## 13. 图文叙事

- **适用内容特征**：用一个场景/人物/故事承载观点，图与文互为注解：品牌墙实景 + 设计理念、人物故事 + 语录、客户案例现场。
- **识别信号**：有场景照片且文字是“设计理念/故事/解读”，而非规格参数。
- **结构示意**（参考视觉：图锚 + 信息栏——左侧大图定场，右侧信息面板分层解读）：
  ```
  ┌────────── action title ──────────┐
  │ ┌────────────┐  栏标题            │
  │ │  场景主图    │  解读段 1         │
  │ │  （焦点）    │  解读段 2         │
  │ │  +caption   │  解读段 3         │
  │ └────────────┘  ─── 原则条 ───    │
  └──────────────────────────────────┘
  ```
- **role 映射**：`image-side`（图 1:1 或竖图）或 `image-hero`（横版场景大图 + 相邻文字）；纯语录观点用 `quote`。
- **视觉焦点**：场景主图；信息栏首段承接图的内容。
- **避免**：图文无关（图必须被文字引用）；信息栏写成参数表（那是产品展示或数据）。

## 14. 视觉焦点通用规则

1. 每页有且仅有一个视觉焦点：主结论数字 / 主图 / 中心节点 / 第一流程节点 / 最高层级。
2. 焦点必须至少占据以下之一：最大字号、最大面积、最高对比（ accent 色或明暗反差）。
3. 其余元素承担视线引导：编号、箭头、动线、明度递减，把视线从焦点带向次重点。
4. QA 检查：遮挡文字后只看版面骨架，3 秒内能指出焦点并说出逻辑类型，否则判不合格。

## 15. 信息分组规则（单页 ≥4 条强制）

1. **触发**：正文信息条目 ≥4 条（列表项、段落、卡片、图表标注均计入）。
2. **分组维度优先级**：对象（谁）→ 阶段（何时）→ 属性（哪类）→ 价值（为何）。按首个能把条目分成 2–4 组的维度归组。
3. **组约束**：每组 2–4 条；每组提炼一个名词短语组标题（≤10 字），组标题必须在页面上可见。
4. **组间关系决定主导逻辑**：组与组平等 → 并列；有先后 → 流程/递进；有主次 → 层级/中心辐射；两两对照 → 对比。
5. **落版**：每组对应一个独立视觉区块（卡片 / 栏 / 层 / 节点 / 象限），组内条目再排主次；区块之间留白或分隔线明确。
6. **超限处理**：归组后 >4 组、单组 >4 条、或组标题提炼不出 → 拆页；禁止压缩字号、减少留白硬塞。

## 16. 参考方案版式原则提炼（视觉表达借鉴）

以下来自品牌空间设计方案（走廊文化墙全案）的版式逻辑，作为 13 类结构的视觉表达参考，不替代组件库 role，只约束“结构如何被看见”：

1. **单一焦点**：封面与每一页都只有一个主视觉锚点（大标题 / 主体装置），其余元素退后。
2. **路径化阅读**：用连续曲线 / 编号 01–05 / W01–W07 把多节点串成一条视线动线，观众按编号顺序阅读，流程、时间轴、递进页必须显式给出阅读方向。
3. **图锚 + 信息栏**：大幅场景图定场，右侧信息面板按“标题 / 规格 / 理念 / 机制”分层解读——图文叙事与产品展示页的默认骨架。
4. **显式编号建立秩序**：L1–L4（层级）、01–05（流程）用编号把层级与顺序外化，观众不看正文也知道结构与先后。
5. **结构即隐喻**：时间长河（时间轴）、原点发散（中心辐射）、层叠爆炸图（层级）——让版面骨架本身表达逻辑关系，而不是用文字解释关系。
