# LAYOUT PATTERNS

本文件是「视觉布局决策引擎」的第二步查表依据：**页面逻辑 → 页面布局（layout pattern）**。

在四步强制链路中的位置：

```
① 页面逻辑识别（语义五步判断，见 page-logic-patterns.md）
② 选择 layout pattern（本文 12 种，显式记录选型理由）
③ 生成视觉蓝图（落盘 state/visual_blueprints.md，逐页 8 字段）
④ 生成 HTML（build_ir 消费蓝图写入 IR，渲染层按蓝图落版，QA 门禁核验）
```

铁律：
- 禁止从文字内容直接进入 HTML；缺①②③任一步，QA 判失败。
- 每页布局必须落在本文 12 种 pattern 之内；未覆盖的布局需求先补登记，禁止临场发明。
- **连页变体禁令**：连续多个内容页不得使用完全相同的布局签名（pattern + 变体）。同一 pattern 连页出现时，必须使用可辨识变体（主体区域切分、焦点位置、区块节奏至少一项不同）。完全相同的"横条列表"连页出现直接判 QA 失败。
- 布局叠加在语义层之上，不替代五步判断：逻辑类型决定"内容是什么关系"，layout pattern 决定"关系如何被看见"。

## 0. 蓝图落盘格式（state/visual_blueprints.md）

每页一行，机器可读表格，列序固定：

| 页码 | 布局pattern | 变体 | 视觉焦点 | 标题位置 | 主体区域 | 辅助信息区域 | 留白比例 | SVG需求 | 图片需求 | 选型理由 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

- `布局pattern`：本文 12 种之一（中文名或 pattern key 均可，见映射表）。
- `变体`：slug（如 `grid-2x2` / `hub-left` / `loop-3`），连页判重以 `pattern + 变体` 为布局签名。
- `视觉焦点 / 标题位置 / 主体区域 / 辅助信息区域 / 留白比例 / SVG需求 / 图片需求 / 选型理由`：八字段必填，空缺即 QA 判失败。

## 1. 中心节点 + 分支（center-hub）

- **适合什么内容**：一个核心概念/主体派生多个分支（应用、触点、特性、价值项）；"一核多点"的中心辐射、策略统领多线。
- **页面视觉焦点**：中心节点（最大面积 + 最高对比，占据视觉重心）。
- **标题位置**：顶部左侧通栏，action title 一行。
- **主体区域**：中心节点容器（大卡片/大容器，页面积 20%–30%）+ 2–5 个分支卡片环绕或单侧排布。
- **辅助信息区域**：分支卡片内条目说明 + 底部 takeaway 强调栏。
- **推荐信息数量**：中心 1 个 + 分支 2–5 个，每分支 1–3 条。
- **留白比例**：≥35%，中心节点四周留白必须大于分支区间距。
- **是否需要 SVG**：可选（中心核与分支间的辐射连接线用细线 SVG 时更贴切）。
- **是否需要图片**：否（有高权重主体图时中心核可承载图片，退化为产品英雄图）。
- **不适合什么场景**：分支有严格先后顺序（改路径式流程）；无中心概念可言的平等并列（改矩阵/非对称图文）。

## 2. 三模块闭环（tri-loop）

- **适合什么内容**：首尾相接的循环链路：价值闭环、PDCA、增长飞轮、三重相互强化。
- **页面视觉焦点**：循环中心的主张句，或价值最高的一环。
- **标题位置**：顶部通栏。
- **主体区域**：3（至多 4）个节点卡 + 闭合环形箭头（SVG），节点围合中心主张。
- **辅助信息区域**：中心主张说明 + 底部 takeaway。
- **推荐信息数量**：3–4 个节点，每节点 1–2 条。
- **留白比例**：≥35%，环内外留白分明，禁止节点挤成横排列表。
- **是否需要 SVG**：是（闭合环/回授箭头是闭环语义的唯一可信表达）。
- **是否需要图片**：否。
- **不适合什么场景**：单向无回授的流程（改路径式流程）；节点超过 4 个（先归并为阶段）。

## 3. 路径式流程（path-flow）

- **适合什么内容**：有先后顺序的步骤/阶段链路：设计→打样→量产→验收；认知逐阶加深的路径。
- **页面视觉焦点**：终点节点的交付物，或当前所处节点。
- **标题位置**：顶部通栏。
- **主体区域**：一条显式方向动线（横轴/阶梯/折线）串起 3–6 个节点，编号显著；递进语义用阶梯上行变体（ascend），平等环节用链式变体（chain）。
- **辅助信息区域**：每个节点下挂 1–2 条说明 + 底部 takeaway。
- **推荐信息数量**：3–6 个节点，每节点 1–2 条。
- **留白比例**：≥30%，节点间距大于节点内边距。
- **是否需要 SVG**：是（方向箭头/连接线；阶梯变体需要抬升基线）。
- **是否需要图片**：否。
- **不适合什么场景**：节点绑定日历日期（改时间轴）；无先后的并列（改矩阵）。

## 4. 时间轴（timeline）

- **适合什么内容**：强绑定日历时间的信息：过去—现在—未来、roadmap、里程碑、年代演进。
- **页面视觉焦点**："现在"节点或下一个里程碑。
- **标题位置**：顶部通栏。
- **主体区域**：一条时间主轴（默认横向），节点按时间悬挂，每节点必须含 日期＋事件＋结果。
- **辅助信息区域**：节点说明 + 底部 takeaway。
- **推荐信息数量**：3–6 个节点。
- **留白比例**：≥30%，"现在"节点可放大 1.2–1.5 倍占据焦点。
- **是否需要 SVG**：可选（主轴与节点标记默认由组件 CSS 承载；特殊纪元标记可用 SVG）。
- **是否需要图片**：否。
- **不适合什么场景**：节点无日期（说明是流程或递进，改用路径式流程）。

## 5. 对比构图（compare）

- **适合什么内容**：两方/两态在同一维度上的对照：A vs B、before/after、本品 vs 竞品、近距收藏 vs 远距传播。
- **页面视觉焦点**：对照后的结论条，或差异最大的一行。
- **标题位置**：顶部通栏。
- **主体区域**：左右（或上下）两个等大对照区块 + 中央分界（竖线/VS 标记），同维度逐行对齐。
- **辅助信息区域**：底部结论条（对照唯一判断）+ takeaway。
- **推荐信息数量**：每侧 2–4 个维度行。
- **留白比例**：≥30%，中央分界带留白必须显著，禁止两栏贴死。
- **是否需要 SVG**：可选（分界标记/胜负高亮可用 SVG）。
- **是否需要图片**：否（两侧为产品图对照时改产品英雄图双联变体）。
- **不适合什么场景**：三方以上对照（改矩阵）；只列两面事实不给结论。

## 6. 数据大数字（big-number）

- **适合什么内容**：证据主体是数字的页面：KPI、目标对比、同比环比、经营结果。
- **页面视觉焦点**：最大的核心数字（最大字号，全页无可竞争者）。
- **标题位置**：顶部通栏。
- **主体区域**：1 个主数字 + 2–4 个次级数字卡片，每个数字必须带目标对比/同比/基准上下文。
- **辅助信息区域**：数字下方的口径说明 + 底部 takeaway。
- **推荐信息数量**：数字 3–5 个；口径说明每条 ≤2 行。
- **留白比例**：≥40%，数字区留白是全 12 种 pattern 中最高的一档。
- **是否需要 SVG**：否（count-up 动画由组件承载）。
- **是否需要图片**：否。
- **不适合什么场景**：数字无对比口径；明细行列规整的台账（改表格 + 矩阵）。

## 7. 矩阵（matrix）

- **适合什么内容**：两个维度交叉定位的信息（重要性×紧急性等象限），或多组并列条目的网格化承载（2×2 / 2×3 格阵）。
- **页面视觉焦点**：主结论指向的目标象限（通常右上）或首格。
- **标题位置**：顶部通栏。
- **主体区域**：2×2 或 2×3 等格阵，格与格等宽等高；每格一个信息组/条目组，格标题可见。
- **辅助信息区域**：维度轴标注（象限用法）+ 底部 takeaway。
- **推荐信息数量**：4–6 格，每格 1–3 条。
- **留白比例**：≥30%，格间距一致且 ≥24px。
- **是否需要 SVG**：可选（象限轴线用 SVG 时维度更明确）。
- **是否需要图片**：否。
- **不适合什么场景**：维度超过两个（改层级空间结构）；只有一个格子有内容（信息量不足，改非对称图文）。

## 8. 左文右图（text-image）

- **适合什么内容**：文字论述为主、右侧配一张高权重场景/产品图定场；图文叙事的标准骨架。
- **页面视觉焦点**：右侧主图（面积最大）。
- **标题位置**：顶部左侧，与正文同栏。
- **主体区域**：左栏（5–6/12 宽）标题 + 论述 + 信息组；右栏（6–7/12 宽）独立容器图片（contain，不出血）。
- **辅助信息区域**：图片 caption 条 + 底部 takeaway。
- **推荐信息数量**：左栏 3–5 条（≥4 条先归 2–3 组）。
- **留白比例**：≥30%，左右栏间槽 ≥34px。
- **是否需要 SVG**：否。
- **是否需要图片**：是（无图项目禁止使用，按冲突裁决规则降级）。
- **不适合什么场景**：无图项目；图片只是点缀而非叙事主体（改非对称图文）。

## 9. 非对称图文（asym-mix）

- **适合什么内容**：主从关系明确但无高权重图片的图文页：一侧主结论/焦点区块，另一侧 2–3 个信息组；也承载"左因右果"等推导构图。
- **页面视觉焦点**：窄栏的焦点区块（主结论/结果/核心主张），用对比或体量突出。
- **标题位置**：顶部通栏，或窄栏顶部。
- **主体区域**：非对称双栏（5:7 或 4:8），宽栏放 2–3 个信息组卡，窄栏放焦点块；可镜像（anchor-right 变体）。
- **辅助信息区域**：焦点块内支撑句 + 底部 takeaway。
- **推荐信息数量**：4–8 条，归 2–3 组。
- **留白比例**：≥32%，宽窄栏比例差必须可辨识（禁止 6:6 伪非对称）。
- **是否需要 SVG**：可选（因→果方向箭头可用细线 SVG）。
- **是否需要图片**：否（有图即升级为左文右图/主图+细节）。
- **不适合什么场景**：两组信息完全平等且体量相同（改矩阵）；需要图片定场的叙事页（改左文右图）。

## 10. 产品英雄图（product-hero）

- **适合什么内容**：页面主角是具体产品/作品/界面：纪念徽章、设备、仪表盘大图，卖点围绕主体展开。
- **页面视觉焦点**：产品主体大图（占页面积 ≥40%）。
- **标题位置**：左上角，与主体图同场不叠字。
- **主体区域**：产品大图独立容器（contain）+ 环绕或侧排 2–4 个卖点标注。
- **辅助信息区域**：底部证据条（3–4 个验证点）+ takeaway。
- **推荐信息数量**：卖点 2–4 条，证据 3–4 条。
- **留白比例**：≥35%，主体图四周净空。
- **是否需要 SVG**：可选（卖点与主体间的标注引线）。
- **是否需要图片**：是（无产品图禁止使用；概念主体可用生成式视觉容器承载时降级为主图+细节）。
- **不适合什么场景**：图片出血/叠字（PROJECT_IMAGES.md 硬约束）；卖点超过 4 条不分组。

## 11. 一张主图 + 1–3 个细节（hero-details）

- **适合什么内容**：一个整体 + 局部放大：产品全景 + 工艺细节、场景主图 + 关键局部解读。
- **页面视觉焦点**：主图；细节图/细节卡按编号 1–3 引导阅读。
- **标题位置**：顶部通栏。
- **主体区域**：主图大容器（60%–70% 面积）+ 1–3 个细节槽（小图或细节卡），细节与主图位置呼应。
- **辅助信息区域**：细节说明文字 + 底部 takeaway。
- **推荐信息数量**：主图 1 + 细节 1–3。
- **留白比例**：≥32%，细节槽间距一致。
- **是否需要 SVG**：可选（主图到细节的呼应引线/编号标记）。
- **是否需要图片**：是（至少 1 张主图；细节可为图或文字卡）。
- **不适合什么场景**：细节超过 3 个（拆页或改图集）；无图（改非对称图文）。

## 12. 层级空间结构（hierarchy-space）

- **适合什么内容**：上下包含/高低秩序的信息：L1–L4 分层、战略→战术→执行、金字塔能力模型、空间纵深分区。
- **页面视觉焦点**：最高层 L1（或塔尖）。
- **标题位置**：顶部通栏。
- **主体区域**：3–5 层分层条/层叠结构，显式编号 L1…Ln，自上而下或自内而外展开；层宽/明度逐级变化表达空间纵深。
- **辅助信息区域**：每层右侧一句作用说明 + 底部 takeaway。
- **推荐信息数量**：3–5 层，每层 1–2 条。
- **留白比例**：≥32%，层间间距一致。
- **是否需要 SVG**：可选（层叠纵深/塔形剪影用 SVG 更贴切）。
- **是否需要图片**：否。
- **不适合什么场景**：层与层只是平等并列（改矩阵）；层级超过 5 层（先归并）。

## 13. 页面逻辑（13 类）→ layout pattern（12 种）映射表

多对多映射：一个逻辑类型可映射多个 pattern（按优先级取首个满足资源约束的），一个 pattern 也可服务多个逻辑类型。

| 逻辑类型 | 首选 pattern | 备选 pattern（按优先级） | 映射说明 |
| --- | --- | --- | --- |
| 并列 | ⑦ 矩阵 | ⑨ 非对称图文 → ① 中心节点+分支 | 条目平等无主次用矩阵格阵；有焦点条目用非对称 |
| 对比 | ⑤ 对比构图 | ⑨ 非对称图文（镜像对照变体） | 两方对照专用；多维对照改 ⑦ |
| 因果 | ⑨ 非对称图文（左因右果） | ① 中心节点+分支（果为中心） | 结果区必须是焦点 |
| 流程 | ③ 路径式流程 | ④ 时间轴（节点带日期时） | 步骤编号 + 方向动线 |
| 时间轴 | ④ 时间轴 | ③ 路径式流程 | 节点必须含日期 |
| 递进 | ③ 路径式流程（ascend 阶梯变体） | ⑫ 层级空间结构 | 程度渐强用阶梯上行；上下包含改 ⑫ |
| 中心辐射 | ① 中心节点+分支 | ⑩ 产品英雄图（中心核为产品图） | 中心核即焦点 |
| 闭环 | ② 三模块闭环 | ① 中心节点+分支（回授中心变体） | 首尾必须闭合；节点 >4 先归并 |
| 矩阵 | ⑦ 矩阵 | ⑫ 层级空间结构 | 两维交叉专用 |
| 层级 | ⑫ 层级空间结构 | ⑦ 矩阵（规整网格变体） | L1 为焦点，显式编号 |
| 数据 | ⑥ 数据大数字 | ⑦ 矩阵（明细格阵变体） | 核心数字最大字号 |
| 产品展示 | ⑩ 产品英雄图 | ⑪ 主图+细节 → ⑧ 左文右图 | 主体图占 ≥40% 面积 |
| 图文叙事 | ⑧ 左文右图 | ⑪ 主图+细节 → ⑨ 非对称图文 | 图锚定场，文栏分层解读 |

### 冲突裁决规则（按序执行）

1. **资源约束优先**：pattern 声明「是否需要图片 = 是」而本项目无可用图片时，该 pattern 禁用，沿备选链降级（例：图文叙事 ⑧→⑨，产品展示 ⑩→⑨/①）。降级必须写进选型理由。
2. **逻辑忠实优先于布局偏好**：禁止为追求布局多样而把内容塞入不承载其逻辑的 pattern（如把并列硬画成闭环）。
3. **连页去重**：选定 pattern 后检查上一内容页布局签名；若相同，优先换用同逻辑下的备选 pattern，其次换用同 pattern 的可辨识变体（变体必须在主体区域/焦点位置/区块节奏至少一项上不同）。
4. **焦点唯一**：两个 pattern 都适用时，取能让"语义登记的唯一视觉焦点"占据最大面积/对比的那个。
5. **容量兜底**：条目数超过 pattern 推荐信息数量上限时，先按语义层分组规则归组；仍超限则拆页，禁止压缩留白硬塞。

### 组件库 role 落点

pattern 决定空间构图，role 是组件库中的渲染落点，二者解耦：

| pattern | 首选 role | 说明 |
| --- | --- | --- |
| ① 中心节点+分支 | two-column（hub 变体） | 中心核大卡 + 分支卡 |
| ② 三模块闭环 | two-column（loop 变体，含环形 SVG） | 节点围合中心主张 |
| ③ 路径式流程 | timeline / two-column（chain 变体） | 方向动线 + 编号节点 |
| ④ 时间轴 | timeline | 日期主轴 |
| ⑤ 对比构图 | compare / two-column（vs-split 变体） | 双侧对照 + 分界 |
| ⑥ 数据大数字 | kpi | 大数字 + 口径 |
| ⑦ 矩阵 | two-column（grid 变体） / table | 格阵承载信息组 |
| ⑧ 左文右图 | image-side | 文栏 + 图容器 |
| ⑨ 非对称图文 | two-column（asym 变体） | 非对称双栏 |
