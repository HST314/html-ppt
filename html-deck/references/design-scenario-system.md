# DESIGN SCENARIO SYSTEM（页面场景识别系统）

本文件定义 html-deck 的 **page 级页面场景体系**：每一页生成前必须先回答两问——**"这一页属于什么场景？"**、**"为什么选择这种设计？"**——并把判定结论作为版式选型的上游输入。

与其他文档的分工（互不替代）：

- `NARRATIVE.md`：**deck 级场景**（客户汇报型 / 产品发布型 / 技术分享型 / 自定义），决定章节顺序与叙事节奏（总线①）。
- **本文件**：**page 级场景**（10 类），决定单页版式选型倾向（总线③）；「推荐布局」全部映射到 `layout-patterns.md` 现有 12 种 pattern 与 `html-layout-system.md` 五子系统，不新造版式。
- `page-logic-patterns.md`：内容 → 13 类逻辑（这一页是什么关系）；`layout-patterns.md`：逻辑 → 12 种 pattern（关系如何被看见）；`html-layout-system.md`：pattern → 空间落版。本文件是上述链路的最上游——**先定场景，再走逻辑 → pattern → 蓝图**。

触发时机：执行流程总线第③步（页面任务定义）。页面任务决定页面场景；场景判定结论逐页落盘 `state/page_semantics.md`「页面场景」列，并作为蓝图「页面类型」字段的唯一取值口径（见 `html-layout-system.md` §0）。

| deck 级场景 | page 级场景配额倾向 |
| --- | --- |
| 客户汇报型 | 数据页、成果展示页、案例页配额高（数据先行章 + 证据章）；产品介绍页少；流程页用于"过程与方法"章 |
| 产品发布型 | 品牌价值页（痛点/洞察）、产品介绍页（方案/演示/优势）配额高；流程页承载路线图；数据页承载验证 |
| 技术分享型 | 项目方案页（架构）、流程页（原理/实现）、数据页（验证）配额高；案例页承载"坑与经验" |

## 1. 页面场景判定流程（总线③强制）

逐页按以下次序判定，**一页一个唯一场景**：

1. **先看故事线位置（骨架页优先）**：第 1 页 → 封面页；章间过渡页 → 章节页；第 2 页目录 → `目录页(toc)`（骨架保留项，见 §2 注）；收束段两页 → 总结页（倒数第 2 页=行动形式，最后页=结束形式）。
2. **内容页按页面任务分流**（页面任务决定场景）：

| 页面任务 | 候选 page 级场景（按内容特征取其一） |
| --- | --- |
| 提出判断 | 品牌价值页（价值主张）/ 项目方案页（方案主张）/ 数据页（判断以数字为证时） |
| 展示证据 | 数据页（数字证据）/ 案例页（实例证据）/ 成果展示页（交付证据） |
| 解释机制 | 流程页（步骤链路）/ 项目方案页（架构分层）/ 产品介绍页（产品机制） |
| 请求决策 | 总结页-行动形式（行动项）/ 项目方案页（待批方案） |
| 过渡收束 | 封面页 / 章节页 / 总结页-结束形式 |

3. **判定记录落盘**：`state/page_semantics.md` 表格「页面场景」列（<!-- TASK-010 fix -->枚举 = 10 类业务场景 + 1 个骨架保留项 `目录页(toc)`）；蓝图「页面类型」列与之保持一致，两处同为 QA 核对点。
4. **选型引用**：蓝图「选型理由」必须以"本页为 X 场景……"开头引用判定结论，回答"为什么选择这种设计"（模板句见 §3 各场景卡）。

## 2. 五属性量规（量化区间全库统一）

**信息密度**（单页信息条目总数 / 正文总字数，1920×1080 画布）：

| 档位 | 条目数 | 字数 | 适用 |
| --- | --- | --- | --- |
| 极低 | ≤3 条 | ≤40 字 | 骨架页（封面/章节/总结-结束形式） |
| 低 | 3–5 条 | 40–120 字 | 产品介绍页等视觉主体页 |
| 中 | 5–10 条（归 2–4 组） | 120–260 字 | 多数内容页 |
| 高 | 10–16 条（归 3–4 组） | 260–420 字 | 项目方案页等结构页上限；超出拆页 |

**图片比例**（图片面积 / 页面积；生成式背景单独标注，不计入内容图比例）：

| 区间 | 含义 |
| --- | --- |
| 0% | 无图页（纯结构/数据/流程页，符号与色块承载） |
| 10–30% | 点缀/辅助图 |
| 30–50% | 图锚页（左文右图类） |
| 40–70% | 主图页（产品英雄图/主图+细节类） |
| 100% 底衬 | 生成式背景（封面/章节/总结-结束形式，art DNA 双路径） |

## 3. 10 类页面场景卡（场景 × 五属性 + 选型理由模板）

### 3.1 封面页

- **识别信号**：deck 第 1 页，建立唯一主题。
- **推荐布局**：组件库 `cover` role；`html-layout-system.md` §2 Flex 纵向居中堆叠（kicker→标题→lede→pill 行）+ §4 色块系统（art DNA cover 生成背景 + scrim 压字）。
- **信息密度**：极低（主标题 + 副题 + meta 行，≤3 条 / ≤40 字）。
- **图片比例**：生成式背景 100% 底衬；有主视觉图时内容图 0–40%。
- **标题结构**：kicker/eyebrow（项目代号）→ 主标题（全 deck 最大字号）→ 副题一句 → meta 行。
- **视觉重点**：主标题（或主视觉图），全页唯一焦点。
- **选型理由模板**："本页为封面页（deck 第 1 页）：任务是建立唯一主题，故以 art DNA cover 生成背景定场、§2 Flex 居中堆叠承载主标题，信息密度压至极低档，让观众第一眼只记住项目名与主题句。"

### 3.2 章节页

- **识别信号**：章间过渡页，storyline 章节序列登记位置。
- **推荐布局**：组件库 `section` role；§2 Flex 居中/左对齐堆叠 + §4 色块系统（art DNA section 生成背景，转场强化）；重复元素跨页同位（平行一致）。
- **信息密度**：极低（章节编号 + 章节名 + ≤1 句导语）。
- **图片比例**：生成式背景 100% 底衬；内容图 0%。
- **标题结构**：大章节编号（mono/accent）+ 章节名（+ 导语一句）。
- **视觉重点**：章节编号与章节名。
- **选型理由模板**："本页为章节页：任务是转场与节奏分隔，故复用全 deck 平行一致的章节页骨架（§2 堆叠 + art DNA section 背景），只承载编号与章节名，不堆信息。"

### 3.3 品牌价值页

- **识别信号**：讲"我们是谁 / 为何可信 / 价值主张"；信号词：使命、愿景、价值观、优势、为何选择我们。
- **推荐布局**：首选 ① 中心节点+分支（品牌核→价值分支）；备选 ⑦ 矩阵（价值格阵 2×2/2×3）、⑨ 变体 ed-strip（价值条目铺陈）。子系统：§1 Grid 格阵 + §5 信息模块（卡片）+ §4 中心核 accent 面。role：two-column（hub/grid 变体）。
- **信息密度**：中（3–5 个价值点，每点 1–2 条，归 2–4 组）。
- **图片比例**：0–20%（可无图；品牌符号图仅点缀）。
- **标题结构**：kicker + action title（价值主张含判断词）+ 各组组标题。
- **视觉重点**：中心核（品牌主张）或首价值卡。
- **选型理由模板**："本页判定为品牌价值页：内容为一核多点的价值主张（N 个价值分支平等并列），故选 ① 中心节点+分支——品牌核占最大面积承载主张、分支卡落 §1 Grid 环绕；与同 deck 其他并列页以 <变体> 区隔布局签名。"

### 3.4 产品介绍页

- **识别信号**：页面主角是具体产品/作品/界面；信号词：产品名、卖点、功能、规格、界面。
- **推荐布局**：首选 ⑩ 产品英雄图（主体图 ≥40%）；备选 ⑪ 主图+细节（整体+局部）、⑧ 左文右图（论述为主时）、⑤ 对比构图（本品 vs 竞品优势对比时，中央分界 + 结论条）。子系统：§3 图片区域（独立容器 contain 保真）+ §2 Flex 图区/信息栏分配 + §5 卖点标注模块。role：image-hero / image-side / compare。
- **信息密度**：低（卖点 2–4 条 + 证据 3–4 条）。
- **图片比例**：40–70%。
- **标题结构**：action title 左上，与主体图同场不叠字。
- **视觉重点**：产品主体大图。
- **选型理由模板**："本页判定为产品介绍页：主角是产品本体，故选 ⑩ 产品英雄图——主体图占 ≥40% 面积进 §3 独立容器（contain 保真），卖点压缩为 2–4 条环绕标注，视觉焦点唯一落在产品。"

### 3.5 项目方案页

- **识别信号**：方案架构 / 实施路径 / 模块组成；信号词：方案、架构、模块、路径、策略、体系。
- **推荐布局**：首选 ⑫ 层级空间结构（方案分层 L1–Ln）；备选 ⑦ 矩阵（方案模块格阵）、⑨ 非对称图文（主方案+支撑的主从构图）。子系统：§1 Grid 分层格阵 + §5 分层条/卡片模块。role：two-column（layers/grid 变体）/ table。
- **信息密度**：高（4–8 条归 2–4 组，或 3–5 层；不超 16 条 / 420 字上限）。
- **图片比例**：0–30%（架构示意图走 §3 容器）。
- **标题结构**：action title 通栏（含方案核心判断）。
- **视觉重点**：塔尖 L1 / 主格 / 焦点块。
- **选型理由模板**："本页判定为项目方案页：方案为上下包含的 N 层结构，故选 ⑫ 层级空间结构——L1 塔尖为焦点，层宽/明度递变表达空间纵深，每层右侧一句作用说明落辅助区。"

### 3.6 流程页

- **识别信号**：步骤 / 阶段 / 链路 / 路线图；信号词：步骤、阶段、流程、先后、路线。
- **推荐布局**：首选 ③ 路径式流程（chain 平等链 / ascend 递进阶梯）；节点绑定日历改 ④ 时间轴；首尾相接改 ② 三模块闭环。子系统：§2 Flex 链（节点 `flex:1` + 方向符号 `flex-shrink:0`）+ §5 编号徽章模块 + SVG 动线。role：timeline / two-column（chain 变体）。
- **信息密度**：中（3–6 节点，每节点 1–2 条）。
- **图片比例**：0%（符号动线承载；节点配图 ≤20%）。
- **标题结构**：action title 通栏 + 节点编号外化（01–N）。
- **视觉重点**：终点节点交付物 / 当前所处节点。
- **选型理由模板**："本页判定为流程页：内容是有先后的 N 节点链路，故选 ③ 路径式流程 <chain/ascend> 变体——§2 Flex 链等分节点、→ 符号给出阅读方向，终点交付物为焦点。"

### 3.7 数据页

- **识别信号**：证据主体是数字；信号词：KPI、同比、环比、目标、指标、经营结果。
- **推荐布局**：首选 ⑥ 数据大数字；明细台账改 ⑦ 矩阵（明细格阵变体）/ `table` role。子系统：§1 Grid 一行格阵（`repeat(N, minmax(0,1fr))`）+ §5 数据三段式模块（label→巨数→note）+ §4 accent 面。role：kpi / table。
- **信息密度**：中（数字 3–5 个，口径说明每条 ≤2 行；表格 4–8 行）。
- **图片比例**：0%。
- **标题结构**：action title 含核心数字结论。
- **视觉重点**：最大核心数字（全页最大字号，无可竞争者）。
- **选型理由模板**："本页判定为数据页：证据主体是 <核心数字>，故选 ⑥ 数据大数字——核心数字以最大字号独占焦点，每个数字带目标/同比口径落 §5 三段式，留白 ≥40% 突出证据力。"

### 3.8 案例页

- **识别信号**：具体客户/项目实例；信号词：案例、客户名、项目名、实践、落地。
- **推荐布局**：首选 ⑧ 左文右图（案例图定场 + 文栏分层解读）；备选 ⑪ 主图+细节、⑨ 非对称图文（无图时按 背景→行动→结果 三段构图）。子系统：§3 图片区域（图栏定比容器）+ §2 Flex 双栏 + §5 信息模块。role：image-side / image-hero / two-column（asym 变体）。
- **信息密度**：中（背景/行动/结果 3 段，每段 1–3 条）。
- **图片比例**：30–60%。
- **标题结构**：action title 含案例成果（带数字）。
- **视觉重点**：案例主图或结果数字。
- **选型理由模板**："本页判定为案例页：叙事主体是 <案例名> 的实例证据，故选 ⑧ 左文右图——案例图进 §3 定比容器锚定场，文栏按背景→行动→结果分层，结果数字以 `.num` 突出为焦点。"

### 3.9 成果展示页

- **识别信号**：已交付成果 / 成绩汇总；信号词：成果、成绩、交付、达成、累计。
- **推荐布局**：首选 ⑥ 数据大数字（成果 KPI 汇）；备选 ⑦ 矩阵（成果格阵）、⑪ 主图+细节（成果实物）/ `gallery` role（成果图集）。子系统：§1 Grid 格阵 + §5 三段式/卡片 + §3 图区。role：kpi / two-column（grid 变体）/ gallery。
- **信息密度**：中（3–6 个成果项）。
- **图片比例**：20–50%。
- **标题结构**：action title 含成果总量数字。
- **视觉重点**：核心成果数字 / 成果主图。
- **选型理由模板**："本页判定为成果展示页：任务是用已交付成果立信，故选 ⑥ 数据大数字——成果总量数字占焦点，分项成果落 §1 格阵逐项带口径；与数据页的区隔：本页数字为结果汇总而非过程指标，变体取 <变体> 避免与同场景页签名雷同。"

### 3.10 总结页

- **识别信号**：收束段两页——倒数第 2 页（行动形式：决策/行动项）与最后页（结束形式：closing）。
- **推荐布局**：行动形式首选 ⑨ 非对称图文（焦点块=核心行动），备选 ⑦ 矩阵（行动项格阵）；结束形式走组件库 `closing` role，§2 Flex 纵向居中 + §4 art DNA closing 生成背景。role：two-column（asym 变体）/ closing。
- **信息密度**：行动形式中（3–5 行动项，每项含负责人/时间/产物）；结束形式极低（1 标题 + ≤1 短句 + 1 CTA）。
- **图片比例**：行动形式 0%；结束形式生成背景 100% 底衬。
- **标题结构**：行动形式 action title（含决策动词）；结束形式主题句居中。
- **视觉重点**：行动形式=首行动项/焦点块；结束形式=唯一主题句。
- **选型理由模板**："本页判定为总结页（行动形式）：收束段首页要把前文压缩为可执行事项，故选 ⑨ 非对称图文——焦点块承载核心行动，宽栏落 3–5 行动项（负责人/时间/产物三要素齐全）。"

## 4. 反模式（禁止项）

1. **禁止所有页面使用同一个模板**：全 deck 不得套用单一版式；page 级场景判定（§1）即事前分流机制——按场景拉开版式分布（不同场景映射不同 pattern 族），从选型源头制造多样性。**与既有连页版式签名规则的关系**：场景多样性是**事前预防**（总线③生成前按场景分流选型），连页签名检查（`layout-patterns.md` 连页变体禁令、`QA_RUBRIC.md` 反同质化签名核对）是**事后兜底**（总线⑦生成后逐页核对 pattern + 变体签名）；两层都执行，互不替代——只做事后检查会在同 pattern 族内空转，只做事前分流无法拦截执行漂移。
2. **禁止无场景判定直接选版式**：`state/page_semantics.md`「页面场景」列空缺即流程门禁判失败；不得从文字内容跳过场景判定直接进入 pattern 选型。
3. **禁止场景与版式错配**：数据页无数字焦点、流程页无方向动线、产品介绍页无主体图容器等"场景卡五属性不落实"的页面，QA 判失败。
4. **禁止骨架页信息过载**：封面/章节/总结-结束形式必须维持极低密度档；把骨架页当内容页堆信息判失败（closing 过载沿 NARRATIVE.md 既有规则降级处理）。
5. **禁止同场景页面版式签名雷同**：同 deck 内判定为同一场景的页面 ≥2 页时，各页布局签名（pattern + 变体）不得完全相同（章节页平行一致性为例外）；判失败口径见 `QA_RUBRIC.md`「场景判定与场景多样性检查」。
