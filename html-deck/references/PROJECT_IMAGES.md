# 项目图片展示规范

生成或审查任何含项目图片的页面时读取。项目图片负责内容展示，背景负责视觉设计，文字负责信息表达。

## 图片型 PDF：原图与衍生设计的边界

- 项目原图是证据，不是底图。禁止通过 `bg_image`、全页 `cover`、模糊、蒙版、调色或局部裁片把原图伪装成页面背景。
- 每次出现项目原图都必须完整等比 `contain`，保留全部边缘内容；不得裁切、拉伸、压扁或用容器遮掉局部。原图四周可出现用于补齐比例的同色留白，但不能改变原图像素比例。
- 背景、文本框、时间轴/流程和转场必须从项目元素衍生：先提取形状语言、路径、轮廓、色谱和材质关系，再重新绘制为独立组件。衍生设计不得复制项目位图，也不得冒充新的项目证据图。
- 可核验产物为 `image_placements` 与 `derived_components`。QA 必须从 manifest 原图独立复算宽高比，并拒绝 `bg_image`、非 `contain`、超大背景式容器、越界/裁切或实际边界比例不一致；同时对原图执行 EXIF 方向归一化、转 RGB、Pillow LANCZOS `contain` 到 `rendered_bbox`，将页面实际裁片与该基准逐 RGB 像素精确比对（允许平均色差 0），防止保持宽高比的内容裁切绕过；最后检查同源背景、卡片、流程和转场组件覆盖。

## 决策顺序

1. 识别主体、尺寸、比例、说明、权重及 `group_id`；无法判断图片关系时视为互不相关。
2. 先保证主体完整与可读，再决定容器比例；默认 `object-fit: contain`，不得拉伸。
3. 按文字长度与图片比例选择稳定布局：文字左/图右、图左/文字右、文字上/图下、图上/文字下或单图区域。
4. 仅当多图共享 `group_id` 或元数据明确说明同主题、同对象多视角、连续步骤时组合；否则逐图拆页。
5. 用尺寸、间距、留白、对比和位置建立标题→核心内容→项目图片→辅助信息的层级。

## 容器硬约束

- 容器必须是矩形或轻微圆角矩形，`position: relative; overflow: hidden; max-width: 100%; max-height: 100%`。
- 图片必须完全位于容器内，不得压字、跨栏、跨模块、出血、抠图越界或穿插背景装饰。
- 容器只可使用至多两项轻处理：极细边框、轻微圆角、轻微阴影、简单底色；禁止强阴影、发光、多层描边与复杂角饰叠加。
- 图片边缘不得渐隐，不得透明融合，不得拆解成背景装饰；背景元素不得遮挡或穿过图片。

## 裁切与动画

- 图片型 PDF 路线一律完整展示原图，不允许 `cover`；HTML 路线也优先 `contain`，只有用户明确授权裁切且 IR 记录安全区时才可例外。
- 项目图片仅允许一次性 `fade-up`、轻微上移或不超过 1.02 的进入缩放；禁止 Ken Burns、漂浮、持续移动、视差、旋转和越界动画。
- Hover 只允许不超过 1.01 的缩放或轻微阴影变化，且不能改变容器边界。

## QA 阻断项

- 任一图片缺少独立容器、alt、明确 object-fit 或容器 overflow 约束。
- `image-hero` 使用全屏绝对定位、文字叠在图片上、图片作为页面背景。
- 默认 `cover` 且 IR 未记录安全裁切理由。
- 无明确关系的图片被自动组合。
- 项目图片使用持续动画，或任何视觉元素遮挡图片主体。
- 尾页未使用与封面相同艺术 DNA 的 closing 变奏背景。
