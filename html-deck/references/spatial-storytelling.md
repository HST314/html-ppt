# SPATIAL STORYTELLING（空间叙事规则）

本文件定义 html-deck 的**空间表达规则**：版面上的方向与位置关系本身必须承载语义——观众不看文字，只看元素的空间排布，就应读出时间推进、层级关系、生态关系、聚合过程、流程与变化。本文件是「结构即隐喻」（`page-logic-patterns.md` §16）在空间方向侧的执行规则。

与其他文档的分工（互不替代）：

- `page-logic-patterns.md`：内容 → 13 类逻辑（这一页是什么关系）。
- **本文件**：逻辑关系 → 空间方向语义（这种关系在空间上朝哪个方向展开、焦点落在何处）。
- `layout-patterns.md`：逻辑 → 12 种 pattern（关系如何被看见——版式选型）；本文件的六组空间关系全部映射到既有 12 种 pattern，不新造版式。
- `html-layout-system.md`：pattern → 空间落版（Grid/Flex/图片区/色块/信息模块怎么搭）。
- `visual-symbol-system.md`：空间方向上的符号件（编号/箭头/节点/路径等如何承接方向语义）；本文件定"方向表达什么"，该文定"用什么符号表达"。

触发时机：执行流程总线第④步（页面逻辑判断，五步判断之「视觉结构」）与第⑤步（视觉结构选择，pattern 选型与蓝图落盘）查阅；QA 在第⑦步按 §9 核对点核验。

---

## 0. 总原则：空间即语义

1. **方向必须承载逻辑**：页面上任何成片的方向性排布（横排 / 纵排 / 辐射 / 对置）都必须对应 §1–§6 已登记的一种空间关系；不承载逻辑的方向排布视为视觉噪音，按 §8 反模式处理。
2. **默认阅读向量**：观众默认按左→右、上→下阅读。空间规则利用该向量：顺向量表达"推进 / 深入 / 展开"，逆向量表达"回溯 / 汇聚 / 收束"。禁止无登记理由的逆向用法（§8-3）。
3. **一页一组主导空间关系**：与"一页一个主导逻辑"（`page-logic-patterns.md` 铁律）对齐；一页出现两组以上主导空间关系时，先归组、仍冲突则拆页。
4. **空间关系与蓝图对齐**：蓝图「内容区域(主体区域)」（九字段口径见 `html-layout-system.md` §0）的落版方向必须与本页主导空间关系一致，并在「选型理由」中可溯源。
5. **焦点与空间终点重合**：视觉焦点（蓝图「主视觉区域(视觉焦点)」）默认落在空间向量的终点或中心——时间推进的最右端、层级关系的最上层、生态关系的中心核、聚合过程的汇聚点、流程的终点节点、对比布局的结论条（与 `page-logic-patterns.md` §14 焦点规则一致）。

## 1. 左 → 右 = 时间推进

- **语义**：水平轴即时间轴。左端是起点 / 过去，右端是终点 / 未来；元素越靠右，时间上越靠后或阶段上越接近结果。
- **何时用**：内容绑定日历时间或有明显先后的推进叙事——roadmap、里程碑、阶段演进、"过去—现在—未来"。对应逻辑类型：时间轴、流程、递进（`page-logic-patterns.md` §4/§5/§6）。
- **怎么用**：首选 ④ 时间轴（横向时间主轴，节点按时间悬挂，"现在"节点可放大 1.2–1.5 倍），无日期的步骤链路用 ③ 路径式流程（chain 横向链变体）；落版走 `html-layout-system.md` §2 Flex 横向链（节点 `flex:1` 等分）；方向由符号承接——编号徽章 + `→` 字符（accent-2 色，结构与引导色，见 `THEMES.md` 双色分工），符号规范见 `visual-symbol-system.md` §1/§2。视觉焦点落最右端节点（终点交付物）或"现在"节点。典型场景：流程页、项目方案页的实施路径（`design-scenario-system.md` §3.5/§3.6）。
- **禁止事项**：禁止把无时间 / 无先后语义的平等并列横排成时间序（伪造先后，观众会误读为流程）；禁止用右→左表达推进（逆阅读向量，仅"回溯过去"类叙事可使用并须在选型理由中登记）；节点无日期却套用时间轴（改路径式流程）。

## 2. 上 → 下 = 层级关系

- **语义**：垂直轴即等级轴。上方是高层 / 统领 / 目标，下方是低层 / 支撑 / 执行；元素越靠上，层级越高。
- **何时用**：信息存在上下包含或高低秩序——L1–Ln 分层、战略→战术→执行、金字塔能力模型。对应逻辑类型：层级、递进（强调"上下包含"时取层级，`page-logic-patterns.md` §10）。
- **怎么用**：首选 ⑫ 层级空间结构（3–5 层分层条，显式编号 L1…Ln，层宽 / 明度逐级递变表达空间纵深）；骨架页（封面 / 章节 / 结束页）的 kicker→标题→副题→meta 纵向堆叠亦属本规则（标题层级即信息层级）。落版走 `html-layout-system.md` §2 Flex 纵向堆叠 / §1 Grid 分层格阵；层级序号用编号徽章（`visual-symbol-system.md` §1），层间分隔用 1px 发丝线（`--line` token）。视觉焦点落最上层 L1（塔尖）。典型场景：项目方案页的方案分层（`design-scenario-system.md` §3.5）。
- **禁止事项**：禁止把实为平等并列的条目画成上下纵深（伪造主次）；禁止把层级关系横放——横放会被读成时间 / 流程（§1），层级必须纵放；层级超过 5 层先归并（沿用 §10 层级避坑）。

## 3. 中心 → 周围 = 生态关系

- **语义**：中心是核心概念 / 主体，周围是由它派生、与它共生的分支；方向自内向外，表达"一个原点生长出一个生态"。
- **何时用**：一核多点——品牌主张统领多个价值分支、同一视觉 DNA 连接多个触点、一个平台辐射多个应用领域。对应逻辑类型：中心辐射（`page-logic-patterns.md` §7）。
- **怎么用**：首选 ① 中心节点+分支（center-hub）：中心核占页面积 20%–30% 为最大面积 + 最高对比，2–5 个分支卡环绕或单侧排布。落版走 `html-layout-system.md` §1 Grid 环绕格阵 + §4 中心核 accent 面色块（反色文字走 `--on-accent`）；中心核与分支间可用细线 SVG 辐射连接线（`visual-symbol-system.md` §6）。视觉焦点即中心核。典型场景：品牌价值页（品牌核→价值分支，`design-scenario-system.md` §3.3）。
- **禁止事项**：禁止分支之间出现先后顺序（有先后即流程，改 §5 路径线）；禁止无中心核的"伪辐射"（分支平等无主体时改 ⑦ 矩阵）；分支超过 5 个先分组（沿用 §7 中心辐射避坑）。

## 4. 外围 → 中心 = 聚合过程

- **语义**：方向自外向内。多条线索 / 要素 / 证据向一个中心点汇聚，中心是收敛后的唯一结论；表达"散点收束为判断"的聚合过程。
- **何时用**：多因一果的推导收束、多项成果汇总为总量结论、前文要点收束为行动项。对应逻辑类型：因果（多因→一果）、中心辐射的逆向变体（回授中心，`page-logic-patterns.md` §3/§7/§8）。
- **怎么用**：首选 ① 中心节点+分支的回授中心变体（`layout-patterns.md` §13 登记变体：分支卡在外、箭头指向中心结论核）；无中心容器时可用 ⑨ 非对称图文（宽栏多支撑条 → 窄栏焦点结论块）。落版走 `html-layout-system.md` §1 Grid 外围格阵 + §2 Flex 双栏；指向中心的箭头用 `→` 字符或细线 SVG（`visual-symbol-system.md` §2/§6，accent-2 色）。视觉焦点落中心汇聚点（结论核 / 焦点块）。典型场景：总结页-行动形式（前文压缩为行动项）、数据页（多指标汇总结论，`design-scenario-system.md` §3.7/§3.10）。
- **禁止事项**：禁止中心放置非结论物（中心不是收束结论即空间语义造假）；禁止与闭环混淆——首尾相接是循环（§5 闭合路径），多线归一是聚合，二者语义不同不得互画；外围线索超过 5 条先归组。

## 5. 路径线 = 流程

- **语义**：一条显式动线把多个节点串成有序链路，线的走向即推进方向，节点即环节；观众沿线阅读即完成流程理解。
- **何时用**：有先后顺序的步骤 / 阶段 / 链路——设计→打样→量产→验收、认知逐阶加深的路径、首尾相接的价值闭环。对应逻辑类型：流程、递进、闭环（`page-logic-patterns.md` §4/§6/§8）。
- **怎么用**：首选 ③ 路径式流程（chain 平等链 / ascend 递进阶梯），节点绑定日历改 ④ 时间轴，首尾相接改 ② 三模块闭环（闭合环形路径）。落版走 `html-layout-system.md` §2 Flex 链（节点 `flex:1` + 方向符号 `flex-shrink:0`）+ SVG 动线；路径线的规范（连续、有向、串联节点）见 `visual-symbol-system.md` §4，方向箭头见该文 §2。视觉焦点落终点节点交付物或当前所处节点。典型场景：流程页（`design-scenario-system.md` §3.6）。
- **禁止事项**：禁止无节点可串的孤立曲线 / 线条（不串任何节点的线即纯装饰线条，判定标准见 `visual-symbol-system.md` §8）；禁止路径无方向（无箭头 / 无编号递增的链路无法读出先后）；节点超 6 个先合并为阶段（沿用 §4 流程避坑）。

## 6. 对比布局 = 变化

- **语义**：两方 / 两态在同一维度上对置，空间上的差异即内容上的变化——before→after、本品 vs 竞品、方案 A vs 方案 B；中央分界是"变化发生处"。
- **何时用**：同一维度上的两方对照，且对照后要给出"发生了什么变化 / 谁更优"的唯一判断。对应逻辑类型：对比、因果（before→after 推导，`page-logic-patterns.md` §2/§3）。
- **怎么用**：首选 ⑤ 对比构图（compare）：左右（或上下）两个等大对照区块 + 中央分界（竖线 / VS 徽标），同维度逐行对齐，底部结论条承载对照后的唯一判断。落版走 `html-layout-system.md` §2 Flex 双侧栏 + §4 双侧分区底色与分界色条；分界符号规范见 `visual-symbol-system.md` §7（标记）。视觉焦点落结论条或差异最大的一行。典型场景：产品介绍页的本品 vs 竞品、案例页的前后对照（`design-scenario-system.md` §3.4/§3.8）。
- **禁止事项**：禁止只列两面事实却不给结论（无结论即无"变化"判断，对比布局不成立）；禁止三方以上对置（改 ⑦ 矩阵）；禁止两栏贴死无分界（中央分界带留白必须显著，沿用 ⑤ 对比构图留白规则）。

## 8. 反模式（禁止项）

1. **禁止方向空转**：成片的方向性排布不对应 §1–§6 任何一种空间关系（如把并列条目随手横排、随手纵排），视为视觉噪音；方向排布必须能回答"这个方向表达了什么逻辑"。
2. **禁止方向混用**：一页出现两组以上主导空间关系（如左半页做时间推进、右半页做中心辐射），先归组，仍冲突则拆页。
3. **禁止无登记逆向**：右→左表达推进、下→上表达层级上升等逆阅读向量用法，仅当叙事明确为"回溯 / 回落"且写入蓝图「选型理由」时允许；未登记即判失败。
4. **禁止纯装饰动线**：路径线、连接线、分界线上板却不串节点、不指方向、不分区——一律按纯装饰线条判失败（判定标准与正误示例见 `visual-symbol-system.md` §8）。
5. **禁止空间关系与逻辑类型冲突**：并列内容画成单向路径（伪造先后）、层级内容横放成时间轴（伪造时间）、聚合内容画成闭环（伪造循环）——空间语义与 `state/page_semantics.md` 登记逻辑不一致即判失败。

## 9. QA 核对点（汇总）

| 核对点 | 判定口径 | 位置 |
| --- | --- | --- |
| 主导空间关系可指认 | 每页能指认 §1–§6 之一；指认不出即方向空转（§8-1） | 逐页目视 / 蓝图「内容区域」 |
| 与逻辑类型一致 | 空间关系 × 逻辑类型命中 §7 映射表；冲突即判失败（§8-5） | 对照 `state/page_semantics.md` |
| 焦点落点正确 | 视觉焦点落在该空间关系的终点 / 中心（§0-5） | 对照蓝图「主视觉区域」 |
| 逆向使用有登记 | 逆向量用法在蓝图「选型理由」有登记，否则判失败（§8-3） | 对照 `state/visual_blueprints.md` |
| 无纯装饰动线 | 页面线条全部通过纯装饰线条判定（§8-4） | `visual-symbol-system.md` §8 |
| 符号配套合规 | 方向符号 ≤2 种 / 页、token 取色正确 | `visual-symbol-system.md` §0、§10 |
