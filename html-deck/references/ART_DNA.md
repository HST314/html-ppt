# 项目艺术 DNA 规范

仅在生成或审查封面、尾页背景时读取。

## 输入与输出

- 输入：`images/manifest.json` 中所有可读项目场景图或成品图；高权重图决定主视觉，其余图参与来源追踪。
- 输出：`state/art_dna.json` 与 cover/content/section/closing 四类同源 SVG 背景。
- 文字描述必须明确记录：特色主题颜色、线条方向、形状语言、构图重心、质感与留白、版式节奏、光影纹样、空间层次。

## 生成纪律

1. 从像素统计和边缘分布提取视觉事实，禁止仅依据项目行业名称猜测。
2. 全部页面共享同一艺术 DNA：封面展开、章节强化、内容页低权重铺陈、尾页镜像或变奏收束。
3. 保留标题侧安全留白；背景只承载视觉氛围，不嵌入正文。
4. 不得固定使用奖牌、圆环、光柱、科技网格等行业图形。只有输入图片确实支持时，才可由 DNA 参数自然产生相近语言。<!-- TASK-039 --> 装饰层（`svg()` 内部的 `motif`）具体实现见 `references/BACKGROUND_STYLES.md`「背景风格库」：由 `scripts/bg_styles.py` 提供六种参数化构图配方（矢量弧线系/规程标线系/笔触人文系/几何色块系/孔版叠印系/渐变光晕系），按本项目 `state/theme_domain.json` 主题域判定（最高优先级）+ 关键词 + 量化特征三级匹配选择，不是任一项目写死同一种。<!-- TASK-041 -->
5. 无可读图片时退出码非零；只有用户接受降级后，才使用基础主题装饰，并在 QA 报告标注 `art_dna=fallback`。

## 阻断检查

- `source_image_ids` 为空：失败。
- `art_expression` 缓漏任一维度：失败。
- 四类角色背景缺任一个，或 HTML 任一页没有项目视觉层：失败。（<!-- TASK-017 -->「HTML 任一页」含封面/尾页——TASK-017 撤销 TASK-015 的模板回退、恢复四类页面全核对，见文末说明）
- HTML 未内联两个背景或仍包含本地绝对路径：失败。
- 不同项目得到相同 `non_template_signature`：失败。

## 无像素输入：图片 md 解读路径

适用场景：项目没有可读图片（无法像素提取），但存在图片的 md 解读文档（如设计方向 candidate 的图文解读）。此时不得直接落入 `art_dna=fallback` 的裸模板降级，必须以 md 解读作为 art DNA 的视觉事实来源。

- 输入：项目图片 md 解读文档（一份或多份）。Agent 通读后按本规范同一组维度提取视觉事实：特色主题颜色、线条方向、形状语言、构图重心、质感与留白、版式节奏、光影纹样、空间层次。禁止仅依据项目行业名称猜测；每个维度必须能指回 md 解读中的原文描述。
- 清单落盘：Agent 将提取结果写成机器可读清单 `state/art_dna_md.json`，字段：`source_md_ids`（解读文档标识列表）、`dna`（`palette` 至少 3 个 hex 色、`line_language`（纵向生长/横向延展/均衡网格）、`light_focus`/`dark_focus`（九宫格 [x,y]，0–2）、`saturation`、`contrast`）、`art_expression`（覆盖全部 8 维度的文字描述）。
- 代码消费：运行 `scripts/art_dna_from_md.py --md-report state/art_dna_md.json --output state/art_dna.json --assets-dir dist/art`。清单缺任一维度时退出码非零并输出字段级修复清单；通过时生成与图片路径同风格的 cover/content/section/closing 四类同源 SVG 背景（同一套生成器），`art_dna.json` 附加 `source_mode="md"`。
- 生成纪律与图片路径一致：全部页面共享同一艺术 DNA（封面展开、章节强化、内容页低权重铺陈、尾页镜像或变奏收束）；保留标题侧安全留白；不得固定使用行业图形；QA 报告标注 `art_dna=md`。
- 只有既无可读图片、又无图片 md 解读时，才允许使用基础主题装饰降级，并在 QA 报告标注 `art_dna=fallback`。
- md 路径阻断检查：`source_md_ids` 为空失败；`art_expression` 缺任一维度失败；其余阻断检查与图片路径相同（`source_image_ids` 一项由 `source_md_ids` 替代）。

## 色彩发散兜底（多来源色相冲突时不取单一来源色调）

背景：项目可能有多个并列关系的图片/md 解读来源（无主次之分），此前无论像素路径还是 md 路径，`dna.palette` 都只由"权重最高"或 Agent 合并后的单一结果决定——若恰好其中一个来源（哪怕只是被命名为"主视图"）色调与其余来源明显不同，就会让这一个来源的颜色误导整个项目封面/章节/尾页的主题色（真实案例：某项目 5 张并列关系的图，其中一张红色底图因命名为"主视图"被单独当成了整个项目的色彩 DNA，实际主体颜色并非红色）。

- 判定对象：各来源"色彩身份"色，约定取各来源 `dna.palette[0]`（即 `semantic_palette()` 语义里的 dark/基底色，也是 `bg_styles.py` 全程当作背景基色 `p[0]` 使用的那个值）。
- 判定算法与阈值（`scripts/extract_art_dna.py::color_divergence_check()`，md 路径复用同一实现）：把各来源色彩身份色转 HSV，按色相聚类（相邻色相间隔 > 55° 判定为不同阵营边界），若聚出 ≥2 个阵营且阵营中心色相差的最大值 ≥ 120°，才判定为"色彩发散、无法归纳统一主体色彩风格"；同一色系内的深浅/明暗差异（色相接近，仅明度/饱和度不同）、饱和度过低的中性色（黑白灰，阈值 0.15）均不参与判定。判定刻意从严，宁可漏判也不误判，只有真的分辨不出统一主体色彩风格时才触发。
- 触发后的处理：不再从冲突来源里挑一个"赢家"色调，改用内容页正在使用的基础配色兜底（`content_page_base_palette()`：读取 `state/style_report.json` 的 `accent`/`accent_2`——该文件由 `detect_style.py` 在 art DNA 提取之前生成，见下方运行顺序；文件缺失时退化为 `assets/themes/proposal-light.css`（SKILL.md「默认视觉方向」基准主题）的 token：深蓝骨架 `--accent` `#123a6b`/青蓝辅助 `--accent-2` `#1fa8d8`/浅色高亮 `--bg` `#f7fafd`/灰蓝辅助 `--muted` `#55677f`，不引入任何冲突来源自身的色相）。只替换 `dna.palette`，`dna` 的其余维度（线条/构图重心/饱和度/明暗层次等）仍取自既有逻辑选中的主图，不改变背景怎么画。
- 该决策不是静默行为：`art_dna.json` 始终记录 `color_divergence_triggered`（bool）与 `color_divergence_reason`（中文说明，含检测到的阵营数、色相中心、最大色相差或未触发的原因），供人工/QA 追溯。
- 像素路径：自动生效，直接用 `images/manifest.json` 里全部可读图片各自的分析结果比较，无需额外输入。
- md 路径：`state/art_dna_md.json` 目前的 schema 只包含 Agent 合并后的单一 `dna`，不带"每份来源各自的主色"，因此**默认不会触发**此规则（无数据可比较）。若确有多份并列关系的 md 解读来源、希望启用该检测，Agent 可额外登记可选字段 `source_identity_colors`（`{来源标识: 该来源自身色彩身份 hex}`，键需与 `source_md_ids` 对应）；未登记或有效条目不足 2 个时静默跳过，不阻断主产物。

## 主题线条插画装饰机制（TASK-028）

背景：art DNA 四类背景（上文）是从项目图**整体色调/明暗/线条方向**派生的抽象几何背景，负责氛围；本节新增的是更进一步的**具体图形主体**补充层——从项目图片或图片 md 解读中提炼出反复出现、能代表整个项目视觉主题的可识别图形（如"火箭剪影""祥云纹""卫星轨道连线""星尘"），画成极简线条 SVG，以低透明度叠加在已有 art DNA 背景层之上的骨架页留白区，"锦上添花"地呼应主题、丰富画面，不改变、不替代 art DNA 背景本身。

真正的图像语义识别（"认出图里画的是什么"）超出脚本能力范围，本机制采用「Agent 语义提炼 + 脚本负责落盘接入」的分工，且做成可被任意项目复用的通用两段式流程，不是为单个项目手工焊死 SVG：

### 第一段：素材库（跨项目通用，脚本不生成，人工/Agent 逐步积累）

- 位置：`assets/motifs/library/*.svg`。每个文件是一个独立的、极简线条风格的图形素材（`stroke="currentColor"`，不写死颜色，跟随调用处的 `color` 继承当前 accent），素材本身不与任何具体项目绑定。
- 新项目如果需要素材库里没有的图形，Agent 按同样的"简单线条勾勒"风格画一个新文件加进这个目录即可（不建立"每个项目一份专属副本"的重复劳动，跨项目主题相近时可直接复用已有素材）。

### 第二段：项目侧映射（每个项目各自登记，落盘 `state/art_motifs.json`）

Agent 在执行阶段完成 art DNA 生成（像素路径或 md 路径均可）后，若从项目图片/图片 md 解读中识别出足够有代表性、重复出现的图形主体（**不是每个项目都必须有**——没有清晰可识别主体的项目可以不提供此文件，机制自动跳过，不影响其余产出），手写落盘 `state/art_motifs.json`：

```json
{
  "version": "1.0",
  "keywords": ["提炼出的主体关键词，供人工溯源，不参与程序判定"],
  "assets": [
    {
      "id": "素材唯一标识，建议与 library 文件名一致",
      "file": "assets/motifs/library/xxx.svg（相对 skill 根目录；也可给绝对路径）",
      "label": "人类可读说明，如「火箭剪影」",
      "roles": ["cover", "section", "toc", "closing"],
      "position": "motif-pos-tr | motif-pos-br | motif-pos-tl | motif-pos-bl | motif-pos-br-wide | motif-pos-tl-wide | motif-pos-full",
      "opacity": 0.16,
      "size": 320,
      "content_keywords": ["可选：内容页自动选材用的触发词，见下文「内容页通用兜底机制」"]
    }
  ]
}
```

- `roles` 登记这条素材在哪些角色上**始终**显示（原样按登记的位置/透明度/尺寸渲染，允许同一页叠多个素材，如封面同时叠"火箭"+"星尘"）。骨架页（`cover`/`section`/`toc`/`closing`）天然留白大，通常这样静态登记；内容页角色（`bullets`/`image-hero`/`kpi`/... 全部 14 个角色名见 `scripts/common.py::ROLES`）**一般不需要**在这里登记——不登记时由 render_deck.py 的通用兜底机制自动接管（见下一节），不需要每个项目逐条手写。同一个素材可以登记多个角色，不同素材也可以各自只出现在最适配的角色上。
- `position` 决定 CSS 定位预设（样式定义在 `assets/components/motifs.css`，通用外壳，不含任何项目专有配色/命名）；`motif-pos-full` 用于星尘一类"满铺散点"素材，其余单体图形用四角预设，避免拉伸变形。
- `opacity`/`size` 逐条独立登记，不同图形可以有不同强度（如背景星尘可以比火箭主体更淡），不是全局写死一个值。
- `content_keywords`（可选）：内容页自动选材用的触发词列表，见下一节。项目未登记时，内容页自动选材会退化为按页码轮换（仍然可用，只是不带语义针对性）。

### 内容页通用兜底机制（TASK-030）

骨架页每个角色在全篇只出现一次（如 `cover` 只有第 1 页），`roles` 静态登记天然够用。内容页角色（`bullets`/`kpi`/`image-hero`/...）会跨越全部章节反复出现多次，同一个角色在不同章节该呼应不同的主题元素（如"作品深读"章节的徽章详情页该呼应徽章自己描述里提到的元素，"任务纪实"章节该呼应火箭/轨道），静态 `role -> 素材` 映射做不到这一点。因此内容页角色改用动态算法，**项目侧不需要为内容页写任何 `roles` 登记**：

1. `scripts/render_deck.py::select_content_motif()` 对每一页，把标题 + 章节名 + 全部正文段落/列表项拼成一段文本，与每条素材的 `content_keywords` 逐词计数打分，命中最多的素材胜出（同分取登记顺序靠前的）；全部 0 命中时按页码对素材数量取模做确定性轮换（不引入随机数，同一份稿子重复渲染结果一致）。
2. `CONTENT_MOTIF_LAYOUT` 常量表按角色版式（网格铺满型 vs 留白角落型）决定这一页用哪个 CSS 位置预设、多大尺寸、多高透明度上限——数值全部低于骨架页（尺寸约骨架页的 1/3，透明度上限 0.05~0.06），且落点选在该角色版式里逐页截图核对过的留白角，具体规则与依据见该常量表上方的代码注释。
3. 每页最多叠 1 个内容页素材（骨架页允许多个，内容页不允许），避免内容页比骨架页还杂乱。
4. 项目如果确实想为某个内容页角色写死固定素材（不想用动态算法），仍然可以直接在 `roles` 里登记该角色——显式登记永远优先于动态兜底。

### 代码接入（脚本侧，一次性通用实现，不因项目而改）

- `scripts/extract_art_dna.py` 与 `scripts/art_dna_from_md.py` 都接受可选参数 `--motifs`（缺省取 `--output` 同目录下的 `art_motifs.json`）；调用 `scripts/common.py::attach_motifs()` 校验清单、把选中的 svg 复制进 `dist/art/motifs/`，并把可渲染结构（含 `content_keywords`）写入 `art_dna.json` 的 `"motifs"` 字段。清单不存在或校验失败时静默跳过、只在 stderr 记录原因，不阻断 art DNA 主产物。
- `scripts/render_deck.py` 渲染每页时，若 `art_dna.json` 含 `"motifs"`：先看是否有素材显式登记了当前页 `role`（有则原样渲染，可能多个）；没有则看当前 `role` 是否在 `CONTENT_MOTIF_LAYOUT` 里（内容页角色），有则跑 `select_content_motif()` 自动选 1 个素材、套用对应版式参数渲染。两条路径都在 `.project-art-frame` 内追加 `<div class="project-art-motif {position}">` 节点（z-index 位于 art 背景之上、正文之下，`pointer-events:none`，随 frame 一起被裁切，不撑高页面）。
- `scripts/inline_assets.py` 无需改动——它已经通用扫描 HTML 里所有本地 `<img src>` 并内联为 data URI，新增的 motif 图片自动被覆盖。

### 门禁与克制纪律

- 装饰层永远是低透明度补充；骨架页建议 0.10–0.20 量级，内容页建议 0.045–0.07 量级（信息密度更高，需要更保守）。不得成为页面视觉焦点；命中 `final-quality-check.md` V1（可读性）/V4（视觉污染）时按原有阻断规则处理，不因"这是新装饰"而豁免。
- 每次新增/调整 motif 映射后必须逐页截图核对：是否遮挡文字、是否喧宾夺主、是否在多页反复出现时观感协调（贯穿多页使用同一素材呼应主题是被鼓励的，但每处出现都要单独截图确认，不能只截一页就假定其余页面一致）。内容页由于覆盖角色更多、页数更多，风险敞口比骨架页大，逐页核对不能省。
